# CE 五原则速查卡

贴在工位上，每次改上下文前过一遍。

1. **整体设计** — 7 层互联。改 system 会影响 tool 选用，加 RAG 会让 system 指令失效。**别孤立优化一层。**

2. **迭代优化** — 每改一次跑 baseline，看 token / 耗时 / cache 命中 / 完成率。**不凭感觉,凭数字。**

3. **用户中心** — 别为压 token 把 system 削到模型乱答。**指标服务体验,不是反过来。**

4. **可扩展性** — 扛得住 10× 复杂度(10× tool / 10× 历史 / 10× 用户场景)。**一开始就分层 cache。**

5. **可维护性** — CONTEXT.md 是活文档,跟业务演进。**改了上下文代码就回填,别让它腐烂。**

---

> 一句话总纲:**先让上下文 100% 可见,再谈优化。**
> 顺序别反——在每轮重发 3k、还带着暗物质的桶里调 prompt 措辞,就是在漏水的桶里调水温。
